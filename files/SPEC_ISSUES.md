### B-3. §5.12 の `{{translation}}` の適用範囲が未定義

ページ全体で `{{translation}}` を数えると、**EP001 は4個**ヒットします。
しかし実際のセグメントは**2個**です（`妖怪がいる!` と `恐怖の交差点`）。
残り2個は lead 段落より後ろの節にあります。

lead 段落（最初の `==` 見出しより前）に限定すると 2 になり、
`episode title = Yo-kai are Real<br>The Spooky Intersection` とも一致します。

**§5.12 にはこの限定が書かれていません。**
素直に実装すると全310話でセグメント数が水増しされます。

加えて、`episode title` との個数不一致が3件あります。

| 話 | lead の translation | `episode title` の `<br>` 分割 | 状況 |
|---|---|---|---|
| EP031 | 1 | **パラメータ自体が無い** | 対応付け不能 |
| EP063 | 3 | **パラメータ自体が無い** | 対応付け不能 |
| EP146 | 3 | 4 | 個数が合わない |

**推奨**

```

2. セグメント数の決定は {{translation}} の個数を正とする
```

**文字列が違う**ため、文字列一致での対応付けは使えません。出現順で対応させる必要があります。
§5.12 の「出現順で対応」という方針自体は正しいです。

**SPEC 修正案**: §5.12 に lead 段落限定の記述を追加。個数不一致3件の扱いを追記。

### B-5. §9.1 の絞り込み軸に対応するフィールドが §4.1 に無い

**SPEC 修正案**: §9.1 に「軸は `categories` から導出し、対応表は `docs/data/facets.json`

スタッフも infobox にあります（§15.1 の確認済みパラメータのとおり）。

候補を挙げることはできますが、記事の構成（表形式か箇条書きか）によって
パーサの作りが変わるため、**確定してから着手したい**です。

**要確認**: 対象記事名。あるいは「PR3 はスキップして `title_ja_full` を null で進める」
という判断でも第一弾は成立します（この場合 §17 U-1 も自動的に解消）。

**SPEC 修正案**: §6 の「ここからしか取れない」を訂正。取得対象記事を明記。

### B-7. §5.13 の件数照合が、正常データで失敗する

実測値です。

```
XML 内の <page> の総数          4,369
titles.txt の行数              4,364
差                                5
```

差の原因は再取得バッチでの**重複エクスポート**です。4タイトルが重複しています。

```
Kaito Hotei / Kyuntaro Han Jou / Hitotsume-kozo Ou Rou / Shin Oba Shuukayuu
（うち1件は3回出現）
```

**タイトルで重複排除すると 4,364 で完全一致**し、集合差も両方向でゼロでした。

```
titles.txt にあって XML にない: 0件
XML にあって titles.txt にない: 0件
```

§5.13 の「XML から読めたページ数と titles.txt の行数を照合し、食い違ったら止まる」を
素朴に実装すると、**正常なデータで必ず停止します。**

**推奨**: 「タイトルで重複排除したうえで、集合として一致するか照合する」に変更。
件数だけでなく集合差（両方向）をレポートすると、取りこぼしの中身まで分かります。

**補足**: §5.13 の根拠にある**自己閉じ `<text ... />` は実測34件あり、指摘は正しい**です。
この34件を落とすと 4,330 になり、§15.1 の「パーサが認識した4,330件ベース」と一致します。
U-5（34ページの正体）は「本文が空のページ」で確定です。

**SPEC 修正案**: §5.13 の1番を「重複排除後の集合照合」に変更。§17 U-5 を解決済みにする。

## 5. 計測の再現方法

本書の数値は `raw/fandom/*.xml` を以下の手順でパースして得たものです。

```
1. 全13ファイルから <page><title>...</title>...<text ...>...</text></page> を抽出
2. <text ... /> の自己閉じ形式は本文を空文字として扱う（34件）
3. タイトルで重複排除（4,369 → 4,364）
4. 分類:
     #REDIRECT で始まる                      → redirect
     {{yo-?kai}} を含む（case-insensitive）    → yokai
     {{character}} を含む                     → character
     {{episode}} を含む                       → episode
     いずれでもない                            → unclassified
5. テンプレートの切り出しは {{ }} の対応を数え上げて行う（§5.3）
6. セグメント数は lead 段落（最初の \n== より前）の {{translation}} の個数
7. presence 注記は Characters 節の各行から \]\]\s*\(([^)]*)\) を抽出
```

再現用スクリプトが必要であれば `tools/spec_audit.py` として起こします。
§15 の実測値の出典を `tools/` に置く方針（§14.3）とも整合します。
