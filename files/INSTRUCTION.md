このファイルの内容をそのまま Claude Code に渡してください。

## 依頼内容

このリポジトリで `yokai-watch-index` を **Phase 4（フロントエンド・公開）まで一気に完成させて**ください。

まず `CLAUDE.md` を読み、次に `SPEC.md` を通読してください。
`CLAUDE.md` が入口、`SPEC.md` が仕様の本体です。

### 進め方

**PR ごとに私のレビューを待たずに、最後まで通しで進めてください。**
各 PR はブランチを切って作成し、自分でマージして次に進んでください。

```
PR1  リポジトリの足場       .gitignore / LICENSE / README.md / sources.yaml / .env.example
PR2  Fandom パーサ          scripts/parse_fandom.py ＋ §5.13 の自己検証
PR3  ja.Wikipedia 取得      scripts/fetch_jawiki.py
PR4  妖Tube 取得            scripts/fetch_youtube.py ＋ A1 ゲートの測定
PR5  突合                   scripts/match_segments.py
PR6  データ生成             scripts/build_data.py ＋ 禁止キー検査
PR7  フロントエンド          docs/ 一式（§9, §10）
```

PR2 が最も重い想定です（§5.2〜§5.13 の12項目が集中しています）。

## 着手前にやること

**いきなり PR1 を始めないでください。**

`SPEC.md` を通読し、**このまま実装を進めると途中で詰まる箇所**を洗い出してください。

- 仕様に矛盾がある
- 仕様が不足していて実装を決められない
- 前提となるデータやファイルが存在しない
- 複数の解釈が可能で、どちらを選ぶかで後戻りが発生する

見つかったものを**一覧にして私に提示し、そこで一度止まってください。**
私が回答し、`SPEC.md` を更新してから着手します。

「特に見つからなかった」であればそう言ってください。すぐ着手して構いません。

**この工程を飛ばさないでください。** 通しで走らせる以上、
途中で仕様の穴に当たると、そこまでの作業が無駄になります。

---

## 途中で迷ったときのルール

通しで進めるため、判断を3段階に分けます。

### 1. 仕様に書いてある → そのとおりに実装

`SPEC.md` の記述が優先です。**一見不合理に見えても勝手に「改善」しないでください。**
この仕様は実データの計測に基づいており、直感に反する記述にも理由があります。

例: `(anime)` は剥がすが `(Shadowside)` は剥がさない（§5.8）

疑問に思ったら `> **根拠**` ブロックを読んでください。

### 2. 仕様に書いていないが、推奨案を出せる → メモして進む

**手を止めずに、推奨案で実装してください。** そのうえで `DECISIONS.md` に記録します。

```markdown
## D-YYYYMMDD-01  {決めたこと}

- 場面: {どの PR / どのファイルで必要になったか}
- 仕様の状況: SPEC.md に記述がない / §X.Y の記述だけでは決まらない
- 採用: {選んだ案}
- 理由: {なぜそれを選んだか}
- 他の案: {検討して捨てた案と、捨てた理由}
- 後戻りのコスト: 小 / 中 / 大
- 要確認: はい / いいえ
```

**「後戻りのコスト: 大」を付けたものは、必ず「要確認: はい」にしてください。**
私が後でまとめて見ます。

### 3. 推奨案も出せない → 手を止めて聞く

以下のような場合は、無理に進めず止まってください。

- どちらを選んでも大きな手戻りが発生し、判断材料が私にしかない
- `SPEC.md` の絶対制約（§2）に抵触しそう
- データが根本的に足りず、機能そのものが成立しない
- 権利・規約の判断が必要

**推測で進めるより、止まる方が安全です。**

## 記録するもの

### DECISIONS.md（新規作成）

上記ルール2で決めたことをすべて記録してください。
これがないと、後から「なぜこうなっているのか」が追えなくなります。

### STATE.md（新規作成）

長時間の作業になるため、進捗を記録してください。

```markdown
# 進捗

最終更新: {日時}

## 完了
- [x] PR1 リポジトリの足場   #1  merged
- [x] PR2 Fandom パーサ      #2  merged

## 作業中
- [ ] PR3 ja.Wikipedia 取得

## 残り
- [ ] PR4 / PR5 / PR6 / PR7

## 計測結果
（各 PR で得られた数値。SPEC.md §15 との差異があれば明記）

## 引っかかっている点
```

**各 PR のマージ後に必ず更新してください。** 途中で中断した場合、
新しいセッションがここを読んで再開できる状態にしておいてください。

### レポート類

`reports/` に出力するものは `SPEC.md §5.13` のとおりです。
`.gitignore` 対象なのでコミットされませんが、**件数は STATE.md に記録してください。**

## 完了の条件

以下がすべて満たされたら完了です。

```
□ docs/data/ に yokai.json / characters.json / episodes.json / segments.json がある
□ parse_fandom.py が raw/fandom/titles.txt と件数一致する（§5.13）
□ build_data.py の禁止キー検査が動作する
   （禁止キーを混ぜたテストで、実際にビルドが落ちることを確認）
□ docs/index.html をローカルで開いて、図鑑タブとアニメタブが動く
□ docs/manifest.json と apple-touch-icon がある
□ docs/robots.txt に Disallow: / がある
□ 全ページに非公式表記とクレジットがある（§12.1, §12.3）
□ docs/privacy.html がある（§12.4）
□ docs/data/LICENSE が CC BY-SA、ルートの LICENSE が MIT
□ DECISIONS.md と STATE.md が最新
```

最後に、以下を報告してください。

- **できたもの**: 各 PR の内容と、得られた計測値
- **できなかったもの**: 実装を諦めた機能と、その理由
- **要確認の判断**: `DECISIONS.md` のうち「要確認: はい」のもの
- **SPEC.md との差異**: 仕様どおりに作れなかった箇所
- **A1 ゲートの結果**: §11.2 の判定（初代＋♪に絞った実測値）

## 補足

### UI について

`SPEC.md §10.6` に画面仕様があります。先行事例の `no-ri/conan-index-site` と同じ構成です。
デザインに凝る必要はありません。**子どもが iPhone で使えることが要件**です。

### 画像について

`SPEC.md §2.1` のとおり、画像は一切扱いません。
種族・属性・ランクは CSS の色と図形で表現してください（§10.4）。

### データが欠けている箇所

必ず出ます。**隠さず「データなし」と表示してください**（§12.5）。
欠損を埋めようとして推測で補完しないでください。

### 静かに失敗しない

`CLAUDE.md` に書いたとおり、これが最重要の原則です。
処理できなかったものは必ずレポートに出してください。
